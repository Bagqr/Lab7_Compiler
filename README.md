### **Вывод об оптимизации циклов в LLVM**

LLVM применяет к циклам несколько оптимизаций:

- Индуктивная переменная (Induction Variable) заменяется на SSA-форму.
    
- Полное удаление цикла (Loop Deletion) происходит, если результат цикла может быть вычислен на этапе компиляции (как в примере с суммой 0..9).
    
- Частичное разворачивание (Partial Unrolling) по запросу -unroll-count=n копирует тело цикла несколько раз, уменьшая число итераций.
    
- При -O2 агрессивные оптимизации (constant folding, dead code elimination) могут полностью убрать короткий цикл, заменив его константой.

Вопросы и задачи к защите
Список теоретических вопросов и задач к защите лабораторной работы:

1) Роль Clang в экосистеме LLVM
    Clang - это фронтенд LLVM, который выполняет лексический, синтаксический и семантический анализ, строит AST и генерирует LLVM IR.
2) Форматы вывода Clang
    Clang умеет выводить AST в удобочитаемом виде, LLVM IR (текстовый или бинарный), ассемблер и машинный код, включая объектные файлы и исполняемые модули.
3) Трехуровневая архитектура LLVM
    LLVM состоит из трёх частей: фронтенд (Clang) для парсинга языка, оптимизатор (middle-end) для IR, и бэкенд для генерации машинного кода.
4) Отличие LLVM от традиционных компиляторов
    LLVM использует универсальное промежуточное представление IR, что позволяет отделить фронтенд от бэкенда и многократно применять оптимизации независимо от исходного языка и целевой платформы.
5) Отличие в компиляции C и C++ кода в LLVM
    Для C и C++ Clang генерирует почти одинаковый IR, но C++ требует дополнительной обработки: name mangling, работа с классами, виртуальными функциями, исключениями и RTTI.
6) Разделение ответственности между Clang и LLVM
    Clang отвечает за парсинг и диагностику, а LLVM — за оптимизацию и генерацию машинного кода.
7) Отличия Clang и GCC
    Clang быстрее, даёт более понятные сообщения об ошибках и лучше интегрируется с LLVM; GCC старше, поддерживает больше архитектур и имеет свои оптимизации.
8) AST (абстрактное синтаксическое дерево)
    AST — это абстрактное синтаксическое дерево, в котором опущены несущественные детали исходного кода, такие как скобки или разделители.
9) Отличие AST от CST
    AST опускает нетерминалы, которые не влияют на семантику (например, скобки или точки с запятой), тогда как CST сохраняет все детали грамматики.
10) LLVM IR (промежуточное представление кода). Три формы LLVM IR
    LLVM IR — это низкоуровневое платформонезависимое представление кода, существующее в трёх формах: текстовая (файл .ll), память (структуры в C++) и бинарный биткод (.bc).
11) Статическая однократная форма присваивания (SSA) 
    SSA — форма, в которой каждая переменная присваивается ровно один раз, что упрощает анализ потока данных и оптимизации.
12) CFG (граф потока управления)
    CFG — это граф, где вершины — базовые блоки (линейные участки кода), а рёбра — переходы между ними.
13) Генерация кода
    Генерация кода — это этап, на котором LLVM IR преобразуется в машинный код для конкретной архитектуры.
14) Оптимизация кода
    Оптимизация кода — это преобразование программы в эквивалентную, но более эффективную по скорости или размеру.
15) Уровни оптимизации Clang/LLVM
    Уровни оптимизации: O0 (без оптимизаций), O1 (базовые), O2 (стандартные агрессивные), O3 (ещё более агрессивные), Os (оптимизация по размеру), Ofast (с нарушением стандартов для скорости).
16) Локальные оптимизации. Примеры
    Локальные оптимизации работают внутри одного базового блока, например свёртка констант или удаление мёртвого кода.
    Примеры: свёртка констант — x = 5 + 3 заменяется на x = 8; удаление мёртвого кода — удаление инструкции x = y, если x больше нигде не используется; упрощение арифметики — x = y * 1 заменяется на x = y.
18) Глобальные оптимизации. Примеры
    Глобальные оптимизации анализируют всю функцию целиком, например, оптимизация циклов или распределение регистров.
    Примеры: оптимизация циклов — вынос инвариантных вычислений из цикла (вместо for(i) { x = 2 * i; y = x * 3; } вычисление 2*i остаётся, а 3 выносится); распределение регистров — часто используемые переменные помещаются в регистры вместо памяти; удаление недостижимого кода — код после return или безусловного goto удаляется.
20) Межпроцедурные оптимизации. Примеры
    Межпроцедурные оптимизации работают между функциями, например, встраивание функций или удаление неиспользуемых функций.
    Примеры: встраивание функций (inlining) — вызов square(5) заменяется на 25, если функция короткая; удаление неиспользуемых функций — функция, которая нигде не вызывается, не включается в выходной файл; специализация аргументов — передача константы в функцию позволяет свернуть вычисления внутри неё.
